# Форматы данных

## `.vsclass`

`.vsclass` — ZIP-пакет класса для локального импорта учеников, учителей и фотографий. Импорт работает в два шага: сначала staged preview без изменения проекта, затем транзакционная запись выбранной стратегией.

```text
class.vsclass
├── manifest.json
└── assets/
    ├── ivanov.jpg
    └── ...
```

Минимальный `manifest.json`:

```json
{
  "format": "vakha-class",
  "version": 1,
  "class": {
    "schoolName": "Школа №25",
    "className": "4А",
    "academicYear": "2026"
  },
  "students": [
    {
      "externalId": "student-001",
      "firstName": "Александр",
      "lastName": "Иванов",
      "status": "ready",
      "photos": [
        {
          "path": "assets/ivanov.jpg",
          "role": "main",
          "order": 0,
          "mimeType": "image/jpeg",
          "byteSize": 123456
        }
      ]
    }
  ],
  "teachers": []
}
```

Поддерживаемые статусы: `new`, `needs-photo`, `needs-review`, `ready`, `approved`, `hidden`.

Стратегии повторного импорта:

- `append` — добавить всех как новых участников;
- `merge` — обновить совпадения по `type + externalId`, а если `externalId` нет, по типу и ФИО;
- `replace` — заменить текущий список класса в проекте.

Проверки безопасности:

- общий размер пакета — не более 500 МБ;
- не более 5000 файлов;
- абсолютные пути и `..` отклоняются;
- фотографии должны лежать в `assets/`;
- поддерживаются `image/jpeg`, `image/png`, `image/webp`, `image/svg+xml`;
- если указан `byteSize`, фактический размер ресурса должен совпасть;
- preview не записывает участников, фотографии или метаданные проекта.

## `.vsalbum`

`.vsalbum` — ZIP-пакет редактируемого проекта. Он нужен для локальной резервной копии и переноса
альбома между рабочими местами без публикации данных в сеть.

```text
album.vsalbum
├── manifest.json
└── assets/
    ├── asset-id
    └── ...
```

`manifest.json` содержит:

- `format: "vakha-album"`;
- `version: 1`;
- метаданные проекта;
- нормализованный canvas document со страницами, разворотами и слоями;
- участников и фото участников;
- participant overrides;
- список assets с путями, MIME, типом и размером.

При импорте создаётся новый локальный `projectId`, assets и участники получают новые id, а ссылки
из слоёв, фото участников и overrides перекидываются на импортированные записи.

Проверки безопасности:

- общий размер пакета — не более 1 ГБ;
- не более 10000 файлов;
- абсолютные пути и `..` отклоняются;
- каждый asset из manifest должен существовать в ZIP;
- фактический размер asset должен совпасть с `byteSize`;
- данные проходят Zod-проверку перед записью в IndexedDB.

## Аннотации

Аннотации — рабочие материалы проекта. Они хранятся в IndexedDB отдельно от canvas document и не
попадают в альбомный PDF/PNG/JPEG/ZIP. Для передачи правок доступен отдельный экспорт:

- JSON: объект `{ format: "vakha-annotations", version: 1, annotations: [...] }`;
- Markdown: человекочитаемый список с заголовком, статусом, типом, привязками и текстом.

Аннотация может быть привязана к:

- точке или области в миллиметрах;
- странице;
- слою;
- участнику.

Поддерживаемые статусы: `open`, `resolved`, `archived`.
